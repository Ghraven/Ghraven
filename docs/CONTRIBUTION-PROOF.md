# Contribution Proof Notes

This note explains how the public contribution claims on the profile should be read.

## What counts as strong proof

- Merged pull requests in maintained external projects.
- Open pull requests with clear problem statements, tests, and maintainer-ready descriptions.
- Own-repo projects that are runnable, documented, and easy to verify locally.
- Public discussions or issue comments that are specific and helpful.

## What this profile avoids

- Inflating activity with noisy PRs.
- Listing AI tools as human-style contributors.
- Publicly highlighting topics that do not fit the employer-facing profile.
- Claiming verification that was not actually run.

## Maintenance checklist

- Keep the profile badges accurate after regular GitHub sessions.
- Keep selected wins current and remove stale or weak examples.
- Prefer links to runnable demos, tests, and case studies over broad claims.
- Keep transparency wording generic and accountable: AI-assisted, human reviewed.
